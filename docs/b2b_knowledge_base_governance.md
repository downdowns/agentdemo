# B2B 业务知识库治理知识库

## 1. 为什么需要知识库治理

RAG 系统的回答质量高度依赖知识库质量。如果文档过旧、重复、冲突、缺少来源或结构混乱，模型即使检索到了内容，也可能生成不准确或不一致的回答。

## 2. 知识库内容范围

B2B 业务知识库通常包括平台招商规则、供应商入驻规则、商品发布规范、活动规则、售后政策、客服 SOP、运营话术、行业知识、常见问题和内部流程文档。

## 3. 文档治理要求

高质量知识库文档应满足：

- 来源明确：知道文档来自哪个业务团队或规则页面。
- 版本清晰：记录生效时间、更新时间和适用范围。
- 结构清晰：标题、章节、列表和示例便于切分和检索。
- 冲突可控：同一规则不能存在多个互相矛盾版本。
- 权限明确：不同角色能看到的内容不同。

## 4. RAG 文档切分建议

文档切分应尽量保留完整语义单元。规则说明、流程步骤、FAQ、表格解释和注意事项应避免被切得过碎。chunk metadata 应包含 source、chunk_id、业务域、版本和更新时间。

## 5. 缓存与知识库版本

当知识库发生更新时，检索缓存需要考虑失效问题。cache key 可以加入 knowledge_base_version，避免用户继续拿到旧规则下的检索结果。

## 6. 用户反馈闭环

差评样本应回流到知识库治理流程。如果用户反馈回答不准，需要判断是文档缺失、文档过旧、检索失败、排序错误还是模型没有正确使用上下文。
